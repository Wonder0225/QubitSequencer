# `.qfridge` 格式 v1：制冷机项目

`.qfridge` 是独立的 SQLite 文件，`meta.format=qfridge`，`PRAGMA user_version=1`。一个文件保存一台制冷机的当前布线方案；每个样品仍保存在自己的 `.qchip` 中。

| 数据 | 内容 |
| --- | --- |
| `meta` | 格式标记、制冷机名称及可选的 `board_grid:盘号` 格子类型 |
| `samples` | 样品 ID、名称和相对于 `.qfridge` 的文件路径；跨盘符时使用绝对路径 |
| `ports` | 盘号、端口编号、位置和端口类型；同一盘内编号唯一 |
| `assignments` | 每个端口至多一条分配，包含样品、线路用途、引脚、图纸编号、器件和备注 |

关联器件保存样品内器件 ID 和显示名称；缺少样品文件时保留原分配。重新定位时核对已关联器件 ID。端口修改和分配立即保存，支持当前会话中的撤回和恢复；总览只读，进入单盘后可编辑及撤回。

格子类型以 `square` 或 `triangle` 保存在可选元数据中；未登记时 A、B 默认三角格子，其他盘默认正方格子。空白盘通过这条元数据保留名称。坐标使用统一画布格距，三角格子的相邻行距为 √3/2。新建或拖动端口时吸附格点；打开旧项目和切换格子时自动对齐到最近可用格点，保留端口 ID 与分配，自动对齐不作为撤回步骤。旧项目首次自动对齐前生成同目录 `.pre-grid-时间戳-标识.qfridge` 备份。该扩展沿用 v1 表结构，旧版仍能打开数据，但不支持新建盘模板和格子吸附。

迁移的历史线路完整保存在分配记录的 `legacy_json` 中，包含旧 `wiring_lines` 字段和全部 `wiring_details`；器件关联保存在 `devices_json` 中。界面可只读查看迁移原记录。解除分配或删除端口会删除其迁移记录，操作前需确认，并可在当前会话撤回。

从 `.qchip` 迁移前对样品创建 `.pre-fridge-时间戳.qchip` 备份。选中线路使用 SQLite 跨文件事务写入制冷机项目并从样品删除，失败时回滚；未选中的旧记录留在样品文件。迁移不支持撤回；恢复样品备份后，还需检查并处理制冷机项目中的对应分配，避免出现重复记录。请在迁移前关闭其他窗口或程序中打开的同一 `.qchip`；当前迁移要求两个数据库使用 SQLite 回滚日志模式。

ZIP 打包导出使用数据库一致性副本：根目录 `project.qfridge` 保存包内相对引用，每个样品位于 `samples/样品ID/原文件名.qchip`，即使原文件同名也互不覆盖。解压后打开 `project.qfridge`。包内文件与原文件相互独立；导出前有样品不可用时不生成新包。

## 未来的放大／衰减链

制冷机线路将来可以关联按信号传播顺序排列、位于不同温级的衰减、放大及其他元件。实际温级、器件类型、参数、单位和连接规则待实验室提供后再设计；本版不定义新链路结构，也不开发链路编辑、图形化或计算功能。迁移时原有相关历史数据作为原记录保留，不根据端口预设或自动推断。
