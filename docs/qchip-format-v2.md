# `.qchip` 文件格式 v2

`.qchip` 是单芯片、单文件 SQLite 数据库。应用启用外键；`PRAGMA user_version=2` 和 `meta.format=qchip` 用于识别格式。逻辑格点坐标可取正数或负数，`grid_rows`、`grid_columns` 只表示新建时的初始范围，不构成位置边界。编辑视图仅绘制可见区域内的格点，器件按需保存在稀疏坐标上。

## 实体与关系

| 表 | 内容 |
| --- | --- |
| `meta` | 芯片名称、模板、创建时间、初始范围等文本键值。 |
| `devices` | UUID、`qubit/coupler`、子类型、唯一名称、角色、逻辑坐标、显示偏移、备注。 |
| `links` | 一条独立的比特—耦合器物理连接；保存比特 UUID、耦合器 UUID、备注。每个比特—耦合器组合只出现一次。 |
| `couplings` | 两比特直接电容耦合或经耦合器的有效耦合；保存两个比特 UUID、`direct/coupler`、可选耦合器 UUID、备注。 |
| `wiring_lines` / `wiring_assignments` | 制冷机线路、端口、通道及线路到多个器件的映射。 |
| `parameter_definitions` | 稳定参数键、显示名、作用域（比特、耦合器、物理连接或两比特耦合）、分类、类型、单位。 |
| `parameter_records` | 参数历史、工作点、偏置、记录时间、来源、当前值标志；每条记录只能指向一种对象。 |
| `calibration_records` / `attachments` | 实验类型、拟合 JSON、备注及内嵌图片或其他附件的 MIME、SHA-256 和内容。 |

`devices.id`、`links.id`、`couplings.id` 均为稳定 UUID，移动或重命名器件不改变参数关联。比特与耦合器通过 `links` 直接相连；同一耦合器连接两个比特时，软件建立对应的经耦合器 `couplings` 记录。每个耦合器当前最多连接两个比特。删除一段物理连接会删除依赖它的经耦合器两比特关系，另一段连接保留。删除两比特关系会删除其两段物理连接，但保留耦合器器件及其自身参数。

`NULL` 表示未填写，和数值 `0` 不同。每个“对象 + 参数键 + 工作点”最多一条当前记录；修改参数时旧记录变为历史。时间采用含时区偏移的 ISO 8601 文本；0.3.1 起新记录使用北京时间 `+08:00`。旧 UTC 记录保留原始时间，界面和导出按同一时刻换算为北京时间。读写接口传入无时区时间时按北京时间解释，带时区时间则换算后保存。频率默认 GHz、非谐与耦合强度 MHz、寿命 µs、读取功率 dBm、电容 fF、电流 nA。

参数键前缀分别为 `qubit.`、`coupler.`、`link.`、`coupling.`。`link.g_qc` 用于每一侧比特—耦合器强度，`coupling.g_effective` 用于两比特有效强度，`coupling.g_direct` 用于直接电容耦合。用户字段可在对应作用域追加定义。表格和图片使用选定工作点的当前值；空值在表中为空，在参数图中标为灰色。

## v1 升级

打开 v1 文件或执行 `python -m qubit_sequencer migrate 文件.qchip` 时，程序先通过 SQLite 在线备份生成同目录的 `文件.pre-v1.qchip`，再升级原文件。旧的 `coupling.g_q1c`、`coupling.g_q2c` 历史值分别转到对应物理连接的 `link.g_qc`，工作点、偏置、时间和来源保留。升级后再次打开不会重复迁移。备份已存在时，为避免覆盖旧备份，迁移会停止并提示处理备份文件。高于当前版本的文件拒绝写入。

标定结果与附件已有存储接口，完整的标定管理界面后续按实验需求补充。

## 0.3.1 显示兼容

频率显示名采用 `f_{10}`，参数键仍为 `qubit.f01`、`coupler.f01` 等原有键。默认参数的旧显示名通过读取接口映射为新版 TeX 名称；自定义名称保留原值，读取不改写项目。名称支持简单 TeX，上下标与常用符号在界面和图片中排版，表格文件保留输入语法。

最近文件和窗口偏好保存在 QSettings 中，不增加数据库字段，格式版本仍为 v2。
